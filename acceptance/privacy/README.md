# cn-privacy-legal Acceptance Plan

> 律师审阅用草稿。本目录只保存 cn-privacy-legal 后续端到端验收计划，不保存真实客户、真实企业、真实用户、真实系统、真实供应商或真实个人信息。

`cn-privacy-legal` 已进入 MVP 开发阶段。本轮只补充插件能力、模板、参考资料和评测样例，不进行完整端到端验收。

## 计划验收路径

后续将使用虚构消费类 App / 小程序数据合规场景，按以下路径试跑：

1. `cold-start-interview`
2. `personal-info-processing-map`
3. `privacy-policy-review`
4. `data-processing-agreement-review`
5. `privacy-impact-assessment`
6. `data-transfer-triage`
7. `data-subject-request-workflow`

## MVP acceptance 最低标准草案

- 能识别业务场景、处理目的、个人信息类型、敏感个人信息和信息主体。
- 能区分收集、存储、使用、加工、传输、提供、公开、删除、匿名化和去标识化。
- 能审阅隐私政策中的收集清单、第三方共享、用户权利、保存期限、未成年人、跨境和投诉渠道。
- 能审查数据处理协议中的角色、范围、安全措施、分包、审计、删除和责任承担。
- 能生成影响评估初稿，但不得作为正式评估报告。
- 能对数据出境或境外供应商处理做初筛，但不得作出确定合规结论。
- 能整理用户个人信息请求响应流程，但不得直接发送正式答复。
- 高风险和红旗风险必须进入升级事项。
- 法律依据必须标注“待律师核验”。
- 输出必须能被律师、法务或合规负责人继续编辑。
