# Cold Start Interview

## Purpose

收集团队合同审查口径，形成团队专用 practice-profile.md 草稿。

## When to use

首次启用商业合同插件、客户 playbook 更新、新合同类型进入流程或团队风险口径变化时使用。

## Inputs expected

- 团队名称、客户类型、主要行业、常见合同类型
- 我方常见身份：采购方、供应商、服务方、平台方、投资方、被投资方等
- 适用法域、风险偏好、可让步条款、不可接受条款
- 必须升级事项、合伙人或主办律师复核规则、输出格式偏好、审查周期、客户沟通口径、禁止事项

## Workflow

1. 说明访谈产物不是法律意见，只是团队工作流配置草稿。
2. 逐项访谈团队背景、客户画像、合同类型、我方身份和适用法域。
3. 记录风险等级定义、可让步事项、不可接受事项和必须升级事项。
4. 记录合伙人或主办律师复核规则、审查周期、客户沟通口径和输出格式。
5. 生成 practice-profile.md 建议结构，并列出负责律师确认清单。
6. 加入版本记录，并说明后续 contract-review、nda-triage、deviation-memo、renewal-risk-check 如何读取该 profile。

## Output format

输出 `practice-profile.md` 建议结构，至少包含：团队信息、适用法域、客户类型、合同类型、常见我方身份、风险等级定义、条款审查口径、可让步事项、不可让步事项、升级规则、输出风格、常用模板、禁止事项、复核人、版本记录。另附“负责律师确认清单”“版本更新方式”“后续技能读取方式”。

## Quality checks


本技能必须遵守 `shared/guardrails/` 与 `shared/templates/escalation-matrix.md`：

- 所有输出必须标注“律师审阅用草稿”。
- 不得将 AI 输出直接对外发送、提交、签署或作为法律意见使用。
- 必须人工核验法律依据、事实来源、客户材料和引用来源；无来源时写“待律师核验”。
- 真实客户资料、案件材料、合同、证据、交易文件、个人信息和密钥不得提交到公开仓库。
- 输出必须区分事实、风险、建议、待确认事项和升级事项。


- 输出首页或标题必须标注“律师审阅用草稿”。
- 不得虚构法律依据、案例、法规条文编号、法院观点或监管口径。
- 无法核验来源时，写“待律师补充法律依据”“待律师核验法律依据”或“建议律师检索确认”。
- 必须区分事实、风险、建议、待确认事项。
- practice profile 未经负责律师确认前，只能作为试运行配置。
