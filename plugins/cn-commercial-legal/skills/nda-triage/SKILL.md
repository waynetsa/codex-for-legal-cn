# NDA Triage

## Purpose

快速判断 NDA 是否可快速放行、需律师轻量审查或需主办律师/合伙人介入。

## When to use

用于单向或双向 NDA、保密协议和合作洽谈保密条款初筛。

## Inputs expected

- 脱敏 NDA 文本或条款摘录
- 我方身份和披露/接收信息角色
- 谈判背景、是否已有客户标准模板
- practice profile 中的 NDA 放行口径

## Workflow

1. 识别 NDA 是单向还是双向。
2. 检查保密范围、保密期限、例外情形、返还销毁、责任承担、争议解决。
3. 识别竞业、排他、知识产权归属、管辖不利、处罚性责任、业务限制等夹带条款。
4. 按绿色、黄色、红色分级并说明理由。
5. 输出放行建议、需修改条款、待律师核验法律依据和客户确认事项。

## Output format

必须包含：绿色（可快速放行）、黄色（需律师轻量审查）、红色（需主办律师或合伙人介入）、异常条款、是否单向/双向、保密范围是否过宽、期限是否异常、责任是否过重、是否包含竞业/排他/知识产权归属/管辖不利等夹带条款、放行建议。

## Quality checks


本技能必须遵守 `shared/guardrails/` 与 `shared/templates/escalation-matrix.md`：

- 所有输出必须标注“律师审阅用草稿”。
- 不得将 AI 输出直接对外发送、提交、签署或作为法律意见使用。
- 必须人工核验法律依据、事实来源、客户材料和引用来源；无来源时写“待律师核验”。
- 真实客户资料、案件材料、合同、证据、交易文件、个人信息和密钥不得提交到公开仓库。
- 输出必须区分事实、风险、建议、待确认事项和升级事项。


- 输出首页或标题必须标注“律师审阅用草稿”。
- 不得虚构法律依据、案例、法规条文编号、法院观点或监管口径。
- 无法核验来源时，写“待律师补充法律依据”“待律师核验法律依据”或“建议律师检索确认”。
- 必须区分事实、风险、建议、待确认事项。
- 不得因为文本短就默认可放行，必须逐项检查夹带条款。
