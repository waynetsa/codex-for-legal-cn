# Cold Start Interview

## Purpose

建立并购项目的角色、交易结构、重大性阈值、红旗风险和输出口径。

## When to use

首次启用并购插件、新项目启动、交易结构变化或客户报告格式调整时使用。

## Inputs expected

- 团队名称、项目负责人、复核人
- 买方/卖方/目标公司/投资人立场
- 交易类型、目标公司行业、适用法域
- 重大性阈值、资料室结构、红旗风险定义
- 交割条件口径、披露清单口径、报告格式、升级规则、客户沟通风格、禁止事项

## Workflow

1. 说明访谈产物是项目 playbook 草稿，须由项目负责律师确认。
2. 记录交易角色、交易类型、目标行业和适用法域假设。
3. 定义重大性阈值、红旗风险、披露口径和交割条件口径。
4. 约定资料室目录、文件命名、引用来源占位和报告格式。
5. 生成 practice-profile.md 并加入版本记录与负责律师确认清单。

## Output format

输出项目 playbook/practice-profile.md 草稿，包含团队信息、交易角色、交易类型、目标行业、适用法域、重大性阈值、风险等级定义、红旗风险、交割条件口径、披露口径、输出风格、升级规则、常用模板、禁止事项、复核人、版本记录。

## Quality checks


本技能必须遵守 `shared/guardrails/` 与 `shared/templates/escalation-matrix.md`：

- 所有输出必须标注“律师审阅用草稿”。
- 不得将 AI 输出直接对外发送、提交、签署或作为法律意见使用。
- 必须人工核验法律依据、事实来源、客户材料和引用来源；无来源时写“待律师核验”。
- 真实客户资料、案件材料、合同、证据、交易文件、个人信息和密钥不得提交到公开仓库。
- 输出必须区分事实、风险、建议、待确认事项和升级事项。


- 输出首页或标题必须标注“律师审阅用草稿”。
- 不得虚构法律依据、案例、法规条文编号、法院观点或监管口径。
- 无法核验来源时，写“待律师补充法律依据”“待律师核验法律依据”或“建议律师检索确认”。
- 必须区分事实、风险、建议、待确认事项。
- 重大性阈值不明确时必须列为待律师确认。
