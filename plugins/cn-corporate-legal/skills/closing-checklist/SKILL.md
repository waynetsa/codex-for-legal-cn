# Closing Checklist

## Purpose

形成可跟踪的交割条件、交割文件、交割后义务和客户决策事项清单。

## When to use

用于投资、股权转让、资产收购、重组项目签署前后交割管理。

## Inputs expected

- 交易结构摘要、交易文件草稿或条款清单
- 尽调问题台账、披露事项、客户决策事项
- 项目时间表、责任分工、交割条件口径

## Workflow

1. 区分交割前条件、交割日文件和交割后事项。
2. 为每项列明责任方、状态、截止时间、阻碍因素、依赖文件。
3. 识别需要客户决策或合伙人升级的事项。
4. 对法律依据和交割条件有效性写“待律师核验法律依据”。
5. 输出可用于项目周会的交割跟踪表。

## Output format

必须包含：交割前条件、交割日文件、交割后事项、责任方、状态、截止时间、阻碍因素、升级事项、依赖文件、客户决策事项。

## Quality checks


本技能必须遵守 `shared/guardrails/` 与 `shared/templates/escalation-matrix.md`：

- 所有输出必须标注“律师审阅用草稿”。
- 不得将 AI 输出直接对外发送、提交、签署或作为法律意见使用。
- 必须人工核验法律依据、事实来源、客户材料和引用来源；无来源时写“待律师核验”。
- 真实客户资料、案件材料、合同、证据、交易文件、个人信息和密钥不得提交到公开仓库。
- 输出必须区分事实、风险、建议、待确认事项和升级事项。


- 输出首页或标题必须标注“律师审阅用草稿”。
- 不得虚构法律依据、案例、法规条文编号、法院观点或监管口径。
- 无法核验来源时，写“待律师补充法律依据”“待律师核验法律依据”或“建议律师检索确认”。
- 必须区分事实、风险、建议、待确认事项。
- 不得把未签署或未确认条件写成已完成。
