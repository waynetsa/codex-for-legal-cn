# Cold Start Interview

## Purpose

建立争议解决团队在案件类型、客户角色、证据标准、时间节点和升级规则上的统一口径。

## When to use

新案件类型、团队首次使用插件、重大案件启动或案件策略阶段变化时使用。

## Inputs expected

- 团队名称、案件类型、客户角色：原告/被告/第三人/申请人/被申请人
- 法院或仲裁机构、诉讼目标、商业目标
- 风险偏好、证据标准、时间节点管理规则
- 保全策略、报告格式、开庭准备要求、升级规则、禁止事项

## Workflow

1. 说明本访谈生成案件 playbook 草稿，须由主办律师确认。
2. 记录案件类型、客户角色、法院或仲裁机构、诉讼目标和商业目标。
3. 定义证据标准、事实争议程度、时间节点管理和保全策略。
4. 约定 intake、时间线、证据目录、争点表、庭前准备和周报格式。
5. 生成 practice-profile.md 并加入复核人和版本记录。

## Output format

输出案件 playbook/practice-profile.md 草稿，包含团队信息、案件类型、客户角色、常见法院或仲裁机构、诉讼目标、风险等级定义、证据标准、保全策略、输出风格、时间节点规则、升级规则、常用模板、禁止事项、复核人、版本记录。

## Quality checks


本技能必须遵守 `shared/guardrails/` 与 `shared/templates/escalation-matrix.md`：

- 所有输出必须标注“律师审阅用草稿”。
- 不得将 AI 输出直接对外发送、提交、签署或作为法律意见使用。
- 必须人工核验法律依据、事实来源、客户材料和引用来源；无来源时写“待律师核验”。
- 真实客户资料、案件材料、合同、证据、交易文件、个人信息和密钥不得提交到公开仓库。
- 输出必须区分事实、风险、建议、待确认事项和升级事项。


- 输出首页或标题必须标注“律师审阅用草稿”。
- 不得虚构法律依据、案例、法规条文编号、法院观点或监管口径。
- 无法核验来源时，写“待律师补充法律依据”“待律师核验法律依据”或“建议律师检索确认”。
- 必须区分事实、风险、建议、待确认事项。
- 证据标准和时间节点必须由主办律师确认。
