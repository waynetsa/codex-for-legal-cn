# Chronology Builder

## Purpose

把散乱事实、证据摘要和日期线索整理成案件事实时间线。

## When to use

用于案件分析、证据整理、庭前准备、代理词或答辩状草稿前的事实梳理。

## Inputs expected

- 脱敏事实陈述、聊天记录摘要、合同节点或会议纪要
- 证据编号、证据名称和形成时间
- 诉请或抗辩方向、已知争点

## Workflow

1. 抽取日期、事件、参与方和证据来源。
2. 区分已由材料支持、待核实、双方存在争议的事实。
3. 说明每个事件对诉请或抗辩的意义。
4. 标注证据缺口、待核实事项和关联争点。
5. 无法确定日期时使用“日期待确认”，不得补造。

## Output format

表格字段必须包含：日期、事件、参与方、证据来源、事实争议程度、对诉请或抗辩的意义、待核实事项、证据缺口、关联争点。

## Quality checks


本技能必须遵守 `shared/guardrails/` 与 `shared/templates/escalation-matrix.md`：

- 所有输出必须标注“律师审阅用草稿”。
- 不得将 AI 输出直接对外发送、提交、签署或作为法律意见使用。
- 必须人工核验法律依据、事实来源、客户材料和引用来源；无来源时写“待律师核验”。
- 真实客户资料、案件材料、合同、证据、交易文件、个人信息和密钥不得提交到公开仓库。
- 输出必须区分事实、风险、建议、待确认事项和升级事项。


- 输出首页或标题必须标注“律师审阅用草稿”。
- 不得虚构法律依据、案例、法规条文编号、法院观点或监管口径。
- 无法核验来源时，写“待律师补充法律依据”“待律师核验法律依据”或“建议律师检索确认”。
- 必须区分事实、风险、建议、待确认事项。
- 同一事实多来源矛盾时必须并列呈现。
