# Cold-start Interview

## Purpose

生成 `cn-regulatory-legal` 的监管合规团队 practice profile 草稿，帮助律师、企业法务和合规负责人明确服务对象、行业范围、监管主题、事实核验规则、法规来源核验规则、整改跟踪规则和律师复核节点。所有输出均为“律师审阅用草稿”。

## When to use

- 第一次为监管合规团队启用本插件时。
- 团队行业范围、客户类型、风险偏好、监管材料类型或复核规则发生变化时。
- 准备把律所内部监管合规 playbook 写入私有 profile 前。

## Inputs expected

- 服务对象：企业法务、合规、审计、风控、董办、管理层、业务部门、律所合规团队。
- 行业类型：金融、互联网平台、数据、广告、影视传媒、医药健康、教育、游戏、消费品、制造业、跨境业务等。
- 常见监管事项：许可资质、广告营销、数据合规、反不正当竞争、消费者权益、价格、反垄断、商业贿赂、行业准入、内容合规、平台责任、安全生产等。
- 监管材料类型：监管问询、检查通知、整改通知、处罚告知、处罚决定、监管函、合规自查表、内部整改报告。
- 风险偏好、必须升级事项、事实核验规则、法规来源核验规则、管理层报告格式、整改跟踪规则和律师复核节点。

## Workflow

1. 先确认所有材料均为虚构或脱敏，不使用真实监管问询、处罚决定、客户经营数据或内部调查材料。
2. 访谈服务对象、行业范围、监管主题、材料类型和常见输出格式。
3. 明确哪些事项必须升级：监管调查、处罚风险、现场检查、重大整改、媒体舆情、董事会或管理层决策等。
4. 明确事实核验和法规来源核验规则，要求法律依据统一写“待律师核验”。
5. 生成 practice profile 草稿，记录版本、复核角色和禁止事项。

## Output format

- 律师审阅用草稿声明。
- 团队信息。
- 服务对象。
- 行业类型。
- 常见监管主题。
- 常见监管材料。
- 风险等级定义。
- 必须升级事项。
- 法规来源核验规则。
- 事实核验规则。
- 监管回复审批规则。
- 整改跟踪规则。
- 管理层报告偏好。
- 常用输出格式。
- 禁止事项。
- 律师复核人角色。
- 版本记录。

## Quality checks

- 是否标注“律师审阅用草稿”。
- 是否区分事实、风险、建议、待确认事项。
- 是否避免虚构法规、处罚决定、监管口径或执法趋势。
- 是否写明不得直接作为正式监管提交材料、正式整改报告、正式对外公告或正式合规结论。
- 是否把高风险和红旗风险进入升级事项。

## Escalation / attorney review gate

涉及监管调查、行政处罚、现场检查、责令整改、重大客户经营数据、个人信息、商业秘密、媒体舆情、董事会或管理层决策事项时，必须暂停自动处理并升级给负责律师或合伙人复核。

## Confidentiality notes

不得提交真实客户资料、真实监管问询、处罚决定、整改报告、内部调查材料、个人信息、商业秘密、密钥或私有配置。真实材料应在私有环境中处理，公开仓库仅保留模板、流程和虚构样例。

## Limitations

本技能只生成团队访谈和 profile 草稿，不提供法律意见，不确认具体法律依据、监管口径、违法构成或处罚后果。所有法律依据、事实来源和监管要求均待律师核验。
