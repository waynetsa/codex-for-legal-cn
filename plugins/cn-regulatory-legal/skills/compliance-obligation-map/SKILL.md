# Compliance Obligation Map

## Purpose

帮助律师、企业法务和合规负责人把具体业务模块转化为可跟踪的合规义务清单，识别责任部门、触发条件、制度流程、台账留痕、缺口和升级事项。

## When to use

- 企业需要建立监管合规义务清单。
- 业务涉及资质许可、广告营销、数据合规、平台责任、消费者权益、反商业贿赂、内容合规、安全生产等主题。
- 需要为管理层或业务部门形成整改和责任分工基础。

## Inputs expected

- 业务模块和行业背景。
- 已有制度、流程、台账、报送记录、培训材料。
- 责任部门和业务触发条件。
- 用户提供或虚构的监管主题摘要。

## Workflow

1. 标注“律师审阅用草稿”“不构成法律意见”。
2. 只围绕用户提供或虚构场景展开，不写成全行业百科。
3. 将义务类型拆分为：许可资质、披露告知、审查审批、留痕台账、用户权益、数据或内容管理、培训和内部控制、监管报送或配合。
4. 对每项义务列出业务模块、监管主题、责任部门、触发条件、制度或流程、台账或留痕材料、频率或时点。
5. 将现有材料、缺口、待补材料、风险等级和待律师核验依据分开列示。
6. 对无责任部门、无台账、无制度、触发条件不清、监管报送缺失、资质许可缺失设置中高风险或红旗风险。
7. Markdown 输出应拆成核心义务表、缺口表和升级事项表，避免单一超宽表。

## Output format

- 核心义务表。
- 缺口表。
- 升级事项表。
- 每项均应包含待律师核验依据。

## Quality checks

- 是否避免虚构法规条文、处罚案例或监管口径。
- 是否区分现有材料、缺口、待补材料和升级事项。
- 是否明确责任部门、触发条件和台账留痕要求。
- 是否使用短表结构提升可读性。

## Escalation / attorney review gate

涉及牌照资质缺失、监管调查、重大处罚风险、消费者群体投诉、数据合规或安全生产重大风险时，必须升级给律师和管理层。

## Confidentiality notes

不得输入真实客户经营数据、内部台账、审计材料、个人信息或商业秘密，除非在私有环境脱敏处理。

## Limitations

本技能不出具正式合规结论，不确认具体法律义务是否适用。所有依据和事实均待律师核验。
