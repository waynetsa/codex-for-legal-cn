# 用户个人信息请求响应流程

## Purpose

帮助律师、法务、客服、产品和安全团队整理个人信息请求响应流程，形成受理、身份核验、内部流转、系统操作、记录留痕、风险提示和分类型答复提纲。输出为“律师审阅用草稿”。

## When to use

- 用户提出查询、复制、更正、删除、撤回同意、注销账号、解释说明或投诉处理请求。
- 需要设计内部响应流程、客服口径、系统操作和律师复核节点。

## Inputs expected

- 请求类型、请求渠道、账号或身份核验材料、涉及数据范围。
- 系统操作路径、内部责任部门、历史记录和业务限制。
- 已脱敏或虚构材料；真实请求只能在授权系统中处理。

## Workflow

1. 分类请求类型：查询、复制、更正、删除、撤回同意、注销账号、解释说明、投诉处理。
2. 列出身份核验提示、受理渠道和所需材料。
3. 明确内部责任部门、系统操作步骤、记录留痕和法务复核。
4. 对响应期限、拒绝或限制响应情形写“待律师核验”。
5. 按请求类型生成答复提纲，明确不得直接发送。
6. 对身份无法核验、请求涉及他人信息、删除影响合同履行、安全事件相关请求、未成年人请求、投诉或监管风险触发升级。

## Quality checks

- 是否覆盖八类请求。
- 是否把响应期限和拒绝或限制响应情形写“待律师核验”。
- 是否按请求类型拆分答复提纲。
- 是否没有直接生成正式答复。
- 是否将复杂请求、身份争议、未成年人、投诉升级、监管风险列入升级事项。

## Escalation / attorney review gate

身份无法核验、涉及他人信息、删除影响合同履行、安全事件相关请求、未成年人请求、投诉或监管风险时，必须升级到律师、合规负责人或管理层。

## Confidentiality notes

不得把真实请求、真实账号、真实用户身份材料、真实联系方式、真实客服记录或真实投诉材料放入公开仓库。真实请求只能在授权系统中处理。

## Limitations

本技能不作正式答复，不确认响应期限、拒绝理由或法律依据。所有正式对外答复必须由律师或合规负责人复核。
