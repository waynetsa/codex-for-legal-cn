# AI Tool Intake

## Purpose

帮助律师、法务、IT、安全和合规团队对新 AI 工具、AI SaaS、内部模型、代码助手、文档助手、客服机器人或营销生成工具进行准入初筛。

## When to use

- 新采购 AI 工具或大模型 API。
- 业务部门申请使用 AI SaaS。
- 内部部署大模型或知识库问答。
- AI 用于处理客户资料、合同、案件材料、源代码、财务数据或个人信息。

## Inputs expected

- 工具名称、供应商、部署方式和使用部门。
- 使用目的、输入数据、输出用途、目标用户。
- 是否涉及个人信息、客户秘密、商业秘密、跨境、第三方处理或自动化决策。
- 供应商材料、服务条款、安全说明、隐私政策、DPA 或合同摘要。
- 内部审批规则和 practice profile。

## Workflow

1. 确认工具和项目基本信息。
2. 识别输入数据类型和输出用途。
3. 判断是否涉及个人信息、客户秘密、商业秘密、跨境、第三方处理、自动化决策或对外输出。
4. 标记需要供应商评估、IT 安全评估、法务合规评估和业务负责人审批的事项。
5. 给出初步风险等级和禁止上线条件。
6. 列出待补材料、升级事项和待律师核验法律依据。

## Output format

- 律师审阅用草稿声明
- 工具名称
- 使用部门
- 使用目的
- 处理数据类型
- 是否涉及个人信息
- 是否涉及客户秘密或商业秘密
- 是否涉及跨境或第三方处理
- 是否用于自动决策或对外输出
- 是否需要供应商评估
- 审批角色清单：安全、IT、法务、合规、业务负责人
- 初步风险等级
- 准入结论分级：可低风险试用 / 条件性试用 / 暂缓上线 / 禁止上线，待人工复核
- 上线阶段：试点 / 灰度上线 / 正式上线
- 试点期限、复盘条件、退出条件
- 禁止上线条件
- 待补材料
- 升级事项

## Quality checks

- 是否明确“不作上线批准”。
- 是否识别客户秘密、案件材料、个人信息、商业秘密和源代码。
- 是否列出审批角色，而不是替代审批。
- 是否将高风险和红旗风险放入升级事项。
- 是否识别工具类型、部署方式、使用部门、使用目的、输入数据、输出用途、对外输出、个人信息、客户资料或商业秘密、第三方处理或境外服务、员工个人账号、供应商安全材料、合同和隐私政策。
- 是否区分业务负责人、法务、合规、IT/安全、数据保护负责人或相当角色、管理层审批责任。

## MVP alpha output refinements

准入结论只能是初筛草稿，不得写成正式准入决定：

| 结论 | 适用情形 | 下一步 |
| --- | --- | --- |
| 可低风险试用 | 仅公开资料或虚构资料，内部参考 | 部门负责人备案 |
| 条件性试用 | 涉及普通内部资料，有补充控制措施 | 法务、IT、安全复核 |
| 暂缓上线 | 供应商材料、删除、审计或分包不清 | 补材料后复评 |
| 禁止上线，待人工复核 | 客户秘密、个人信息、商业秘密、源代码或红旗事项未解决 | 管理层和律师复核 |

## Escalation / attorney review gate

涉及客户资料、案件材料、个人信息、商业秘密、跨境、自动化决策、对外输出、核心业务系统、监管行业或重大声誉风险的工具，必须暂停自动准入并交由律师、IT、安全、合规和业务负责人复核。

## Confidentiality notes

公开仓库只能放虚构工具和脱敏说明。真实供应商名称、真实系统架构、真实密钥、真实数据清单不得提交。

## Limitations

本技能只做准入初筛，不代表采购批准、上线批准、安全认证或法律意见。法律依据和主管机关口径均需“待律师核验”。
