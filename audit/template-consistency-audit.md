# Template Consistency Audit

## 通过项

- 8 个插件均包含可编辑 templates。
- 模板总体避免正式法律意见、正式对外发送、正式提交或正式发布口径。
- 主要模板已覆盖风险等级、待补材料、升级事项或律师复核事项。
- 后期插件已经明显采用“核心表 + 缺口表 + 升级事项表”的短表结构。

## 问题项

| 问题 | 影响范围 | 优先级 | 建议 |
| --- | --- | --- | --- |
| 早期核心三插件和后期第二阶段插件的模板风格不完全一致 | 全仓库 | P1 | 统一模板标题、免责声明、风险等级和升级事项位置 |
| 部分 CSV 或宽表模板适合机器处理，但不适合非技术律师快速阅读 | corporate、privacy、regulatory 等 | P2 | 保留 CSV，同时提供 Markdown 分段版本 |
| “客户决策事项”“管理层决策事项”“合伙人升级事项”命名存在业务线差异 | 多插件 | P2 | 统一为“客户/管理层决策事项”和“律师/合伙人升级事项” |
| 部分模板缺少“不得直接发送/提交/发布”的显眼位置 | 个别早期模板 | P1 | 在模板开头统一增加安全提示 |

## 建议统一规则

- 模板开头固定写明：律师审阅用草稿、不构成法律意见、不得直接对外使用。
- 所有模板至少包含事实、风险、建议、待确认事项、待律师核验依据、升级事项。
- 宽表应拆成核心表、缺口表、待补材料表和升级事项表。
- 管理层场景优先使用一页摘要。
- 对外沟通、投诉、监管回复、解除通知、隐私政策等场景必须有“不得直接使用”提示。

## 后续修复优先级

P1：统一免责声明和正式文件边界。

P2：统一字段命名和宽表阅读体验。
