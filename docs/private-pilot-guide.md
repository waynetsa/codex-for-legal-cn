# Private Pilot Guide

本指南面向律所管理者、合伙人、知识管理团队、IT、合规负责人和试点律师。项目仍只产出“律师审阅用草稿”，不提供法律意见。

## 试点目标

- 验证工作流模板能否提升初稿整理效率。
- 验证律师是否能快速识别事实、风险、待补材料和升级事项。
- 验证安全与保密边界是否可执行。

## 适合试点的团队

- 有固定模板和复核流程的业务团队。
- 能提供虚构或严格脱敏材料的团队。
- 有明确负责律师、知识管理负责人和 IT 支持的团队。

## 不适合试点的场景

- 需要直接生成正式法律意见。
- 无法确认材料是否脱敏。
- 涉及高度敏感客户或监管事项且无私有环境。
- 试点团队希望绕过律师复核。

## 推荐试点插件

首批：

- `cn-commercial-legal`
- `cn-litigation-legal`
- `cn-ip-legal`

第二批：

- `cn-ai-governance-legal`
- `cn-privacy-legal`
- `cn-employment-legal`

第三批：

- `cn-corporate-legal`
- `cn-regulatory-legal`

## 试点材料要求

允许：

- 虚构材料。
- 明显脱敏材料。
- 私有环境内经授权材料。

严禁进入公开仓库：

- 真实客户资料。
- 真实案件材料。
- 真实合同。
- 真实员工信息。
- 真实个人信息。
- 真实监管材料。
- 真实交易材料。
- 真实内部批注。
- 密钥和账号信息。

## Practice profile

- 每个团队先填写 practice profile。
- 不写真实客户、真实案件、真实系统或真实人员。
- 写明风险等级、升级事项、输出格式、复核角色和禁止事项。

## Cold-start

试点前先运行对应插件的 cold-start interview，形成团队工作口径草稿，再由负责律师确认。

## 输出质量记录

每次试点应记录：

- 使用插件和 skill。
- 输入材料类型。
- 未使用 AI 预计耗时。
- 使用 AI 后实际耗时。
- 可编辑性评分。
- 风险识别评分。
- 漏报、误报、不可用输出。
- 律师修改意见。

## 停止试点

出现以下情况应立即停止：

- 真实资料进入公开仓库。
- 输出被当作正式法律意见。
- 连接未经批准的真实系统。
- 律师复核缺失。
- 出现保密或权限事件。

## 试点结束后的决策

试点结束后，根据反馈决定：

- 继续只使用模板库。
- 进入更严格的私有部署设计。
- 补充模板、skill 或 guardrails。
- 暂停相关插件试点。
