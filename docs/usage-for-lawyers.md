# 律师使用指南

## 受控脱敏试点流程

律师参与试点前，应先阅读 [私有试点指南](private-pilot-guide.md)、[数据处理与样例脱敏指南](data-handling-and-anonymization-guide.md) 和 [公开仓库与私有部署边界](public-vs-private-deployment-boundary.md)。

建议流程：

1. 使用虚构材料或严格脱敏材料准备试点包。
2. 先运行对应插件的 `cold-start-interview`，形成团队口径草稿。
3. 使用 1 到 2 个具体 skill 生成“律师审阅用草稿”。
4. 由律师记录漏报、误报、编辑量和不可直接使用原因。
5. 使用 [试点反馈表](pilot-feedback-form.md) 汇总评分。

不得把输出直接作为正式法律意见、正式合同文本、正式诉讼材料、正式监管回复、正式制度或正式对外文件使用。

## 从 cold-start 开始

每个团队第一次使用时，先运行对应插件的 `cold-start-interview`。请把团队名称、客户类型、常见合同或案件类型、风险偏好、不可让步事项、升级规则和复核人讲清楚。Codex 生成的 `practice-profile.md` 只是律师审阅用草稿，负责律师确认后才能作为后续技能的工作口径。

## 上传材料前先脱敏

上传给 Codex 的材料应去除真实客户名称、真实案件编号、个人身份信息、联系方式、银行账户、未公开交易价格和商业秘密。公开仓库中只保留模板、流程和明显虚构样例。

## 如何使用输出

- 合同审查输出适合作为初稿风险表和修改建议清单。
- 并购尽调输出适合作为问题台账、交割清单和披露清单草稿。
- 诉讼输出适合作为案件接收表、时间线、证据目录、争点表和庭前准备底稿。

任何法律依据、法律定性、诉讼策略、交易文件处理、对外沟通和正式文书，必须由合格律师复核。无来源时，输出应保留“待律师补充法律依据”或“待律师核验法律依据”。

## 把律所模板接入 templates

先把模板中的真实客户、真实项目、固定报价、个人信息和内部审批信息删除，再放入对应插件的 `templates/`。客户专用模板建议保存在私有环境；公开仓库只放通用模板或明显虚构样例。

## 把合伙人口径写进 profile

把风险等级、不可接受条款、可让步范围、升级规则、客户沟通风格写入本地 `practice-profile.md`。该文件不应提交公开仓库。每次口径更新后，应记录版本和复核人。

## 把输出改成正式文件

1. 回到原始材料核对事实和引用来源。
2. 补充或修正法律依据，确认是否适用最新规则。
3. 由主办律师确认风险等级、客户沟通口径和升级事项。
4. 根据客户授权改写成正式邮件、备忘录、交易文件附件或诉讼文书。
5. 发送、提交、签署或依赖前完成律所内部复核流程。
