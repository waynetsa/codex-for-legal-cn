# Public Repository and Private Deployment Boundary

本项目当前阶段仍是公开模板库，不是生产系统。

## 公开仓库适合存放

- 插件结构。
- Skill 说明。
- 模板。
- 参考检查清单。
- 虚构 acceptance 样例。
- 审计和路线图。
- 安全和保密规则。

## 公开仓库不适合存放

- 真实客户资料。
- 真实案件材料。
- 真实合同。
- 真实监管材料。
- 真实个人信息。
- 真实员工资料。
- 真实交易资料。
- 私有系统配置。
- 密钥、token、API key、Cookie。

## 私有部署可以处理

在具备授权、权限、日志和审计条件下，私有部署可以处理经批准的真实材料。但输出仍为“律师审阅用草稿”，仍需律师或负责人员复核。

## 私有部署前必须具备

- 访问控制。
- 用户权限。
- Matter 隔离。
- 客户隔离。
- 日志。
- 审计。
- 数据留存策略。
- 删除策略。
- 模板审批。
- 输出复核。

## 什么时候可以考虑 MCP

- 已完成安全评估。
- 已确认最小权限。
- 已默认只读。
- 已有日志和审计。
- 已有客户和 matter 隔离。
- 已有连接器审批和撤销机制。

## 什么时候不应接 MCP

- 不能确认资料授权。
- 不能隔离客户或 matter。
- 不能记录访问日志。
- 需要默认写回生产系统。
- 试点团队尚未完成保密培训。
- 输出可能被直接当作正式法律意见。

## MCP 原则

- 最小权限。
- 只读优先。
- 不默认写回。
- 不跨客户检索。
- 不跨 matter 检索。
- 不保存密钥到公开仓库。
