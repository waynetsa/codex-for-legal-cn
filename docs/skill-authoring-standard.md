# Skill Authoring Standard

本标准用于维护 8 个法律工作流插件的 `SKILL.md`。所有 skill 只生成“律师审阅用草稿”，不提供法律意见。

## 统一结构

每个 `SKILL.md` 必须包含：

- YAML frontmatter。
- Purpose。
- When to use。
- Inputs expected。
- Workflow。
- Output format。
- Quality checks。
- Escalation / attorney review gate。
- Confidentiality notes。
- Limitations。

## YAML frontmatter

```yaml
---
name: skill-name
description: 清楚说明何时触发、适用范围和边界
---
```

`description` 应说明：

- 适用场景。
- 主要输出。
- 不提供法律意见。
- 不得直接对外使用的边界。

## 必须使用的项目定位

每个 skill 的正文应明确：

- 输出为“律师审阅用草稿”。
- 不构成法律意见。
- 不得直接对外发送、提交、签署或发布。
- 法律依据、事实、期限、金额、主体、证据和客户决策事项均需人工核验。
- 涉及法律依据时写“待律师核验”。

## 输出必须区分

- 事实。
- 风险。
- 建议。
- 待确认事项。
- 升级事项。

## 禁止使用的过强表述

不得使用以下表达，除非是在“禁止示例”中引用：

- 必然违法。
- 必然构成侵权。
- 必然败诉。
- 可以直接发送。
- 可以直接提交。
- 自动合规。
- 无需律师复核。
- 已经合法有效。
- 监管必然认可。
- 法院必然支持。

## 建议使用的稳健表述

- 初步提示。
- 待律师核验。
- 基于现有材料。
- 需补充事实。
- 建议律师复核。
- 需合伙人或负责人升级。
- 不作最终结论。
- 不得直接对外使用。

## Output format 写法

`Output format` 应优先用短表和分段结构，不建议单一超宽表。最低应包含：

- 草稿标识。
- 事实摘要。
- 风险等级。
- 待补材料。
- 待律师核验依据。
- 建议下一步。
- 升级事项。

## Escalation / attorney review gate 写法

升级闸门应说明：

- 哪些高风险或红旗事项必须升级。
- 升级给谁：负责律师、合伙人、管理层、合规负责人、客户负责人或相应角色。
- 升级前不得直接发送、提交、签署、发布或执行。

## Confidentiality notes 写法

保密说明应写明：

- 真实客户资料、案件材料、合同、个人信息、员工信息、监管材料、交易资料、系统清单、商业秘密不得进入公开仓库。
- 私有环境使用真实材料前必须具备授权、权限控制、日志、审计、客户隔离和 matter 隔离。
- 不得把客户秘密、案件材料、个人信息或商业秘密输入未经批准的 AI 工具。

## Limitations 写法

限制部分应明确：

- 不提供法律意见。
- 不替代律师事实核验和法律检索。
- 不生成正式对外文件。
- 不确认法院、仲裁机构、监管机关、平台或交易对手一定接受某项观点。
- 不接入真实 MCP 或生产系统。
