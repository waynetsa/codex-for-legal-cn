# Post-Release Pilot Plan

## 为什么选择复合试点包

v1 preflight 已重点试跑 commercial、litigation、IP 三个单插件包。本轮 post-release QA 选择 3 个复合试点包，用于覆盖未重点试跑的插件，并检查跨插件组合是否破坏边界。

## 试点包

| 试点包 | 覆盖插件 | 目的 |
| --- | --- | --- |
| corporate-diligence | cn-corporate-legal | 验证并购尽调、问题提取、交割清单、披露清单。 |
| privacy-ai-governance | cn-ai-governance-legal, cn-privacy-legal | 验证 AI 工具上线、个人信息、供应商处理、出境初筛。 |
| employment-regulatory | cn-employment-legal, cn-regulatory-legal | 验证劳动用工争议、监管问询、整改计划。 |

## 本轮目的

- 覆盖 v1 preflight 未重点试跑的插件。
- 检查跨插件组合使用是否仍保持“律师审阅用草稿”定位。
- 检查是否有真实资料风险。
- 检查是否出现 P0/P1。

## 模拟律师角色

- 合伙人：关注风险边界、客户决策、升级事项、对外责任。
- 主办律师 / 资深律师：关注事实结构、证据、材料完整性、输出可编辑性。
- 初级律师：关注是否易用、是否能搭框架、是否减少遗漏。
